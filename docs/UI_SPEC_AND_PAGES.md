# LoopLedger UI Specification & Screen Design

> **Design System:** Tailwind CSS + shadcn/ui  
> **Brand & Colors:** Indigo Primary (`#4F46E5`), Slate Neutrals, Green (`#16A34A`), Amber (`#D97706`), Red (`#DC2626`).  
> **Typography & Spacing:** Inter font, 8px spatial grid, 12px rounded cards (`rounded-xl`). Maximum content width: 1200px.

---

## 1. Global Navigation & Layout

* **Desktop View ($\ge 1024\text{px}$)**:
  * Persistent 240px collapsible left sidebar.
  * Top navigation bar with user profile, role badge, and logout trigger.
* **Mobile View ($< 768\text{px}$)**:
  * Bottom tab bar with 4–5 core role-specific icons.
  * Responsive sheet overlays for modals and filters.
  * Minimum 44px touch targets.
  * Tables adapt into stacked cards.
* **Role-Based Menus**:
  * **Admin**: Dashboard, Customers, Subscriptions, Invoices, Payments, Catalog (Products, Plans, Templates), Pricing (Taxes, Discounts), Billing Run, Team, Audit.
  * **Staff**: Dashboard, Customers, Subscriptions, Invoices, Payments, Inbox.
  * **Customer**: My Subscriptions, My Invoices, Profile.

---

## 2. Shared Components (`src/components/`)

1. **`AppShell`**: Manages sidebar/bottom-bar navigation, user session context, and offline status bar.
2. **`StatusChip`**: Standardized color-coded status badges:
   * `DRAFT`: Gray
   * `QUOTATION`: Blue
   * `CONFIRMED`: Indigo
   * `ACTIVE`: Green
   * `CLOSED`: Slate (with `closeReason` sub-badge, e.g. "Paused")
   * `PAID`: Green
   * `OVERDUE`: Red
   * `CANCELLED`: Slate with strike-through text
3. **`HealthBadge`**: 
   * 🟢 Green: Good standing
   * 🟡 Amber: Invoices 1–30 days overdue
   * 🔴 Red: Invoices $> 30$ days overdue
4. **`MoneyText`**: Formats integer paise to currency: `₹1,23,456.00` using `Intl.NumberFormat('en-IN')`.
5. **`MoneyInput`**: Inputs accept rupee amounts from users; automatically converts to integer paise for API payload.
6. **`DataTable`**: TanStack Table wrapper with search input, status filter chips, sortable column headers, server-driven pagination, skeleton loading states, and empty states.
7. **`ErrorBanner`** & **`OfflineBanner`**: User-facing indicators for network dropouts and API errors.

## 3. Screen Specifications

### Authentication Screens
* **`/signup`**: Public registration form. Includes a real-time reactive password checklist:
  - [x] At least 9 characters
  - [x] At least one uppercase letter
  - [x] At least one lowercase letter
  - [x] At least one special character
* **`/login`**: Email and password fields with error feedback.
* **`/forgot` & `/reset`**: Token-based password recovery flow.

### Admin & Staff Workspaces
* **`/dashboard` (Revenue Radar)**:
  * Top KPI Metric Cards: Active Subscriptions, MRR, Cash Collected This Month, Outstanding AR, Overdue Amount.
  * Charts: Revenue-by-month bar chart, Overdue accounts ageing distribution (1–30d, 31–60d, 61+d).
  * Recent activity and actionable Renewal & Dunning inbox preview.
* **`/customers` & `/customers/[id]`**:
  * Customer index with health badges, search, and contact details.
  * Detail view containing customer info, subscriptions tab, invoices tab, and payment history.
* **`/subscriptions`**:
  * Filterable table (Status, Plan, Expiry).
* **`/subscriptions/new`**:
  * Customer selection $\to$ Plan or Quotation Template selection.
  * Template auto-populates product lines.
  * Dynamic line editor (Product, Variant, Quantity, Tax).
  * Real-time pricing calculation fetched via `POST /api/v1/subscriptions/price` (never calculated on client).
* **`/subscriptions/[id]`**:
  * Prominent **Visual Stepper**: `Draft` $\to$ `Quotation` $\to$ `Confirmed` $\to$ `Active` $\to$ `Closed`.
  * Context-aware action buttons based on plan capabilities (Confirm, Activate, Pause, Resume, Renew, Close Early).
  * Invoices generated by this subscription and immutable audit log timeline.
* **`/billing` (Billing Run Center)**:
  * Billing date picker.
  * **Preview Table**: Previews subscriptions due for billing, calculating invoice totals via dry-run without writing to database.
  * **Run Billing Button**: Confirmation dialog before execution.
  * **Execution Report**: Displays total created, skipped duplicates, and isolated failures.
  * Historical billing run audit table.
* **`/invoices` & `/invoices/[id]`**:
  * Filter by Status and Overdue flag.
  * Bulk selection with **Bulk Confirm** action.
  * Detail page: Customer metadata, period dates, itemized lines with discount & tax breakdowns.
  * Actions: Confirm, Cancel, Send Email, Print / Download PDF (with UPI payment QR code), Record Payment modal.
* **`/payments`**:
  * Audit log of all payments received with payment method, invoice reference link, and notes.
* **`/catalog/products` & `/catalog/plans` & `/catalog/templates`**:
  * Products: Base prices, cost, description, and variant price adjustment sub-table.
  * Plans: Recurrence intervals and capability switches (`autoClose`, `closable`, `pausable`, `renewable`).
  * Quotation Templates: Pre-configured plan and line items with default validity days.
* **`/pricing/taxes` & `/pricing/discounts`**:
  * Tax rate configuration.
  * Discount Rule builder: Fixed / Percentage toggle, threshold criteria (min spend, min seats), date bounds, usage limits, and product vs subscription scope.
* **`/team` (Admin Only)**:
  * Manage staff members, invite staff, deactivate accounts.
* **`/audit` (Admin Only)**:
  * Searchable and filterable system-wide audit trail.

### Customer Self-Service Portal
* **`/my/subscriptions`**:
  * Active subscription cards showing current plan, renewal date, and active seats.
  * Self-service action buttons: Pause subscription (if permitted by plan) and adjust seat quantity.
* **`/my/invoices`**:
  * History of all invoices issued to the customer.
  * Download PDF invoice button.
  * Interactive UPI payment QR code for unpaid invoices.

## 4. Progressive Web App (PWA) & Offline Mode

1. **Serwist Service Worker**:
   * Precaches AppShell assets, CSS, and fonts so the application loads without an active internet connection.
2. **Dexie (IndexedDB) Client Cache**:
   * Caches latest loaded pages for `/invoices`, `/payments`, and `/subscriptions`.
   * When network requests fail, cached records are rendered alongside an `OfflineBanner` displaying last sync timestamp.
3. **Offline Payment Outbox**:
   * Recording payments while offline queues the mutation in a Dexie `outbox` table as `{ id: uuid, invoiceId, method, amount, paidOn, note }`.
   * Automatically flushes outbox items upon `navigator.onLine` reconnection using the client `uuid` as the `Idempotency-Key` header.
